# Why this case exists

The control for `parse/stacked-unary-minus-refused`. A unary minus after a
binary operator is generated by §4.2's grammar and must keep working:
`expr = term *( *WSP ( "+" / "-" ) *WSP term )` and
`term = factor *( *WSP ( "*" / "/" ) *WSP factor )`, with
`factor = [ "-" *WSP ] primary`. So the second operand of any binary operator
may carry its own unary minus.

`a - -b` is 9, `a * -b` is -18, `a / -b` is -2. An implementation that fixes
stacked unary minus by refusing every `-` that follows an operator breaks all
three.

# Why this case exists

`order-rhs = literal / ident`. A `string` is not one of them, so
`if(name < "m", …)` is not generated by `comparison`, is not generated by
`formula`, and the header cell is refused under §9.20.

§4.2 rule 10 gives the reason rather than leaving it to the grammar: `<`, `<=`,
`>`, `>=` "are never textual, because ordering text means collation, collation
is locale-dependent, and §3 fixes NFC and nothing else: `"a" < "B"` is true
in one locale and false in another, and a format whose claim is that two readers
agree cannot have an operator whose answer depends on the reader's locale."

The refusal is the whole of the defence. An implementation that admits a string
here has to give it *some* answer, and every available answer is a collation —
including "compare the host language's strings", which is code-point order in
Python and Go, UTF-16 order in Java and JavaScript, and locale order in C++ with
a global locale imbued. §4.1.8 already refused locale collation for the one
place the format does order text, an `order := by(c)` column, so admitting it
here would reintroduce it in a place with no `order` declaration to blame.

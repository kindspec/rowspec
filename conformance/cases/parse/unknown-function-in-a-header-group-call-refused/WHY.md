# Why this case exists

The header cell `s = median(v where k = @k)` has the shape of a per-row group
aggregate with a function that is not one of the five.

Two §9 entries apply, so both are listed and either passes (§9: "where several
apply, the case names each of them, and reporting any one passes"):

- §9.11 (`unknown-aggregate`): "an unknown aggregate function". §4.2 rule 4:
  "a name before `(` that is in neither list is an unknown function (§9.11)",
  and §7: "An unknown function is refused."
- §9.20 (`malformed-formula`): "a header cell containing `=` whose right-hand
  side is not generated by §4.2's `formula`." `group-call` requires an
  `agg-fn`, `rowrel-call` a `rowrel-fn`, and `expr` has no call alternative,
  so nothing generates `median(`.

No input in a header cell separates the two: any unknown function there is
also outside `formula`. (On a declaration line only §9.11 applies;
`parse/declaration-unknown-function-over-a-missing-column-refused`.)
`parse/known-function-in-a-header-group-call-accepted` is the control.

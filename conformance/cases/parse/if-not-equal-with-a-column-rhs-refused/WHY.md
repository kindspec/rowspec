# Why this pair exists

§9.24: "an `=` or `<>` comparison inside `if` whose right-hand side is an
`ident` (§4.2 rule 10)". §4.2 rule 10: "`if(a = b, …)` is not generated by
`comparison`, while `if(a < b, …)` is. The asymmetry is not an oversight."

**The pair is the test, and §9.24 says so in its own text**: it is "listed
separately only because an implementation that admits `ident` uniformly on both
sides of every comparison operator, which is the natural way to write the
parser, will accept it and then have to invent a text-or-number reading that
§4.2 rule 10 declines to fix."

That implementation passes an accept-only suite and passes a refuse-only suite
that never checks `<`. It fails only when both halves are asserted on the same
shape: `order-rhs = literal / ident` admits the column, `eq-rhs = string /
literal` does not.

The reason for the asymmetry is worth restating because it is not arbitrary:
"for ordering the answer is numeric whatever the operands are, and for equality
it is precisely the question the spelling rule above answers — and with a column
on the right there is no spelling to read."

Measured cost, from rule 10: "121 of 12,697 corpus `if` cells (0.95%)".

# Why this case exists

The header cell `c = median(c where k = @k)` is a per-row group aggregate
whose function is not one of the five, over its own column.

Two §9 entries apply, so both are listed and either passes (§9: "where several
apply, the case names each of them, and reporting any one passes"):

- §9.11 (`unknown-aggregate`): "an unknown aggregate function". §4.2 rule 4:
  "a name before `(` that is in neither list is an unknown function (§9.11)",
  and §7: "An unknown function is refused."
- §9.20 (`malformed-formula`): "a header cell containing `=` whose right-hand
  side is not generated by §4.2's `formula`." `group-call` takes an `agg-fn`,
  `rowrel-call` a `rowrel-fn`, and `expr` has no call alternative, so nothing
  generates `median(`.

The self-reference does not change this. A cycle is a value: §4.2 rule 9,
"**A cycle evaluates to `#REF!(cycle)`**", and such files "are **accepted
files**, not refusals" — but only when nothing else refuses them, because a
value is what the cells of an accepted file hold and §9 lists what an
implementation "MUST refuse". Nothing in rule 9 suspends a refusal for a
column on a cycle. Recognition does not depend on the header at all: §4.2
rule 7 refuses to let "a formula's *acceptance* depend on the header rather
than on its own bytes", and "Recognition is whole-cell" (§4.2). Whether `c` is
on a cycle is a property of the header; whether `median(` is a formula is a
property of the cell's bytes.

The failure this pins is a reader that detects the cycle first, marks `c`
`#REF!(cycle)`, and never inspects the function name. The cell is otherwise
well-formed (`k` is stored, so §9.22 does not apply), the computed cell is
empty, and nothing else in §9 applies.
`parse/known-function-in-a-group-aggregate-over-itself-accepted` is the
control.

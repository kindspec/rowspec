# Why this case exists

The header cell `t = sum(nope where a = "x")` is a group aggregate whose
aggregated column, `nope`, does not exist. The file is accepted.

- **The cell is well-formed.** It is generated by §4.2's `group-call`:
  `sum`, `(`, the `ident` `nope`, `where`, a predicate `a = "x"`, `)`.
  §9.20 (`malformed-formula`) is scoped to a header cell "whose right-hand
  side is not generated by §4.2's `formula`", so it cannot reach this one.
- **§9 has no entry for a missing column.** §9 says "This list is complete.
  Every refusal the format has is below", and no entry names an aggregate,
  in a header cell or a declaration, over a column that does not exist.
- **§4.2 rule 7 settles it for the aggregated column directly.** "`sum(nope)`
  is `#REF!(nope)` ... refusing this one would mean refusing an aggregate
  over any absent column — which contradicts the fixtures that pin `#REF!`
  as the answer, and would make a formula's *acceptance* depend on the
  header rather than on its own bytes."
- **§8 repeats the argument for a predicate name** and says nothing about it
  is specific to where the formula is written: "The leftmost rule reads a
  declaration's right-hand side the same way ... Nothing about it is
  specific to a header cell."

So the header-cell form is a value, `#REF!(nope)`, not a refusal.
`rowrel/header-group-aggregate-over-a-missing-column-is-ref` and
`eval/header-group-aggregate-over-a-missing-column-is-ref` assert that value
on the same bytes.
